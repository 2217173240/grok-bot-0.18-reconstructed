金字塔尖 · 一句话结论
Grok Bot 是一条 把信任编成进程、把对话编成协议流、把诚实编成可执行门禁 的工程主线。读懂它要先分清两件事：回合在哪里调度，模型服务在哪里——原版把 agent 引擎（host）放在远端盒里，桌面应用只是盒的客户端；本仓库另外支持同一个 host 进程跑在本地 Docker 容器里，以及让 Mac coordinator 执行一轮（resolveLocalAdminBox 可以返回 mac-host，SAND_LOCAL_ADMIN_TURN=mac 时路由的 provider 在 Mac 侧执行）。而这个重建项目是同一工程精神的镜像：重建者的证据门禁驱动与原作者的安全边界驱动互为表里。

A

架构：五进程三层沙箱

它是什么

这个桌面应用是个瘦客户端——本地只有 UI 和调度，真正的 agent 引擎（host）通过 broker 返回的 gatewayUrl + token 被连接。host 的运行位置有三种：远端盒（原版默认）、本地 Docker 容器（本仓库自建镜像）、以及 Mac 本机进程。

A1

实证host 不在桌面端，但运行位置有几种。main 通过 connect protobuf 调 broker ensureSandBox 拿到 gatewayUrl+gatewayToken 后才连上盒；local-docker 模式等价替换为 docker run 暴露 127.0.0.1:1340；resolveLocalAdminBox 还可以返回 mac-host，此时 host 作为 Mac 本机进程运行。用户机唯一的本地代理是 local-exec-daemon——这正是"本地工具权限审批"存在的前提。

box-host-connector.ts 的 BrokeredHostConnector.connect · local-docker-host-connector.ts 的 LOCAL_DOCKER_GATEWAY_URL 与 resolveLocalAdminBox
A2

实证回合调度位置与模型服务位置要分开看。即使 host 在盒里，一轮问答也可能在 Mac 侧调度：SAND_LOCAL_ADMIN_TURN=mac 时 inference-router.ts 的路由器接手 sendPrompt，用 Mac 上的 CLI 与凭据执行。判断"文件权限、凭据位置、命令在谁的机器上跑"时，要看这一轮的调度平面，以及 host 进程实际运行在哪里。

B

机制：一次对话 = 路由 × 双层循环 × 事件流

它怎么运转

模型"思考"在 host 的循环里，工具"行动"被抽象成跨进程 protobuf 消息流分发给两个 daemon。事件面有两条产生路径：host 的轮次把模型流转成 InteractionUpdate 事件流；Mac coordinator 的路由器直接合成 transcript 条目并发布 appended/updated 事件。渲染层因此不关心 provider 是谁。

B1

实证路由 = 策略叠加。决策数据只有一处：settings.json 的 inferenceProvider 字段；决策点有两个：coordinator 拦截 sendPrompt + host 按同一 settings 选会话。接入差异：cursor 复用沙箱登录态；codex 直读 ~/.codex/auth.json（强制 0600 普通文件、拒 symlink、401 自动 refresh_token 刷新）；claude-code 用 SDK spawn CLI 子进程；openrouter 直连 + 密钥走 box-secrets。

sand-settings-store.ts 的 getInferenceProvider · inference-router.ts 的 sendPrompt 拦截 · provider-session.ts 的 claudeChildEnv / codexExecutor / claudeExecutor / openRouterExecutor / CLAUDE_LOCAL_TOOLS
B2

实证步数预算 + 特定故障处理。turn 层：上限 5000 步（SAND_AGENT_MAX_STEPS），正常结束条件 = 无工具调用且无排队消息；step 层：边流式收输出边收集工具调用，工具并发执行，结果以 role:"tool" 回喂。上限约束的是循环次数：它不保证任务完成，也不单独约束每一步的等待时间（等待模型响应、工具流与工具 promise 期间没有步级超时）。熔断是特定故障的处理：收到 EXEC_BACKEND_UNAVAILABLE 分类时跳过工具并注入错误结果，避免死循环。超时、取消与"任务真的做完"是三件不同的事，各自需要自己的保证。

turn-agent-composition.ts 的 maxSteps · tool-stream-executor.ts 的双层循环与 EXEC_BACKEND_UNAVAILABLE 分支
B3

实证两条事件产生路径。host 轮次把模型流转成 InteractionUpdate：textDelta / thinkingDelta / toolCallStarted/Delta/Completed / partialToolCall / tokenDelta。Mac coordinator 的路由器不走这条转换：它直接构造 {kind:"send-message"} 条目，经 emitTranscript 发 postEvent("transcript", …)。排查显示与投递问题时，先确认事件来自哪条路径，否则会追错转换层。进程边界即协议边界，脱敏是边界投影的一部分（跨进程投影 redacted proto）。

agent-core/interaction-updates.ts 的 InteractionUpdate · chat-inference-proto/converters.ts（消息↔proto）· inference-router.ts 的 emitTranscript
B4

实证执行分治。agent 只面对 RemoteExecManager 抽象，不知道工具在哪跑：盒内工具 → box-exec-daemon（Connect gRPC）；用户机工具 → local-exec-daemon（带权限门 + 审批）。目标分表面：盒内 Shell/Read vs 用户机 ExternalShell/ExternalRead。插件 MCP 服务器也归这一层：stdio 服务器由盒内 daemon 启动并托管，盒内轮次通过回环桥把工具交给 CLI 子进程，HTTP 服务器仍由后端执行。

agent-exec/remote.ts 的 RemoteExecManager · box-exec-daemon/server.ts 的 BOX_EXEC_DAEMON_PORT · box-exec-daemon/mcp-host.ts 的 BoxMcpHost · shared/node/mcp/routed-mcp-bridge.ts · sand-activity.ts
B6

实证工具参数的搬运纪律。命令型工具的权限回调必须把工具参数原样交回：Claude CLI 用权限结果里的 updatedInput 覆盖工具参数，交回空对象会把模型给出的参数全部抹掉。参数跨进程序列化时在边界处把普通 JSON 转成 protobuf Value，与后端执行端口保持一致。

provider-session.ts 的 claudeToolPermission 与 allowUnchanged · box-mcp-exec.ts 的 toMcpArgs
B5

推断"看起来一致"的代价。cursor 走远端 gateway 原生状态（thinking 原生透传）；routed provider 只有文本 delta，router 合成 transcript 事件——thinking 是合成的 activity 行（250ms pulse 防渲染抖动）、reactions 本地存储。渲染层无法区分 provider，代价是流式细节降级为合成呈现。

C

实践：三层纪律对抗"悄悄漂移"

它怎么防错

重建品的最大风险是"与原版悄悄不一样"。作者的回应是三层可执行纪律——每个脚本都在防一个具体的坑。

C1

实证身份校验：先写临时文件、校验通过才改名。bootstrap 把下载内容写进 .partial（mode 0o600）→ 对临时文件算 SHA-256 → 不符则删除临时文件并抛错 → 相符才 rename 成正式缓存文件。保证是"未通过校验的下载不会成为正式缓存文件"：临时文件在磁盘上确实出现过，它的信任状态与正式文件不同，不要在它上面做读取、解包或执行。DMG 与 app.asar 另外有固定哈希；补丁机制 fail-closed：patch 前 stockSha256 必须匹配、锚点必须恰好出现一次、patch 后 patchedSha256 必须匹配，任一不符直接 throw。供应链纪律：每条获取路径（LFS / 缓存 / 下载 / env）都校验。

scripts/bootstrap-runtime.mjs · scripts/lib/config.mjs · scripts/apply-third-party-patches.mjs
C2

实证闭包审计：把"不允许什么"写成代码。audit-renderer-closure.mjs：clean 入口只允许 TS/TSX/JS/CSS，禁止任何 import 触碰不可变原版 artifact；audit-runtime-composition.mjs：forbiddenEvidencePrefix = "src/app/"，生产区域用显式 Set 枚举（新增不会静默替换、删除会报错）；audit-ui-provenance.mjs：@evidence 注解必须位于白名单根目录内。防的是审计范围漂移。

scripts/audit-*.mjs
C3

实证双轨验证：交付检查各管一件事。要分清四种保证：输入身份（DMG / app.asar 的哈希与 LFS 指针）；产物组成（verify.mjs 的 ASAR 必需文件清单含 4 个 agent-isolation worker、禁 source map、确定性 manifest 逐项比对、干净渲染器禁出现原版 chunk 名；其中"≥1000 条源码证据标记"统计的是固定产物里上游 bundle 的 // src/ 注释行数，证明的是产物带有证据标注，不能证明重建代码的行为正确）；启动检查（native-e2e-check.mjs 真实 spawn 打包 App，断言进程存活、renderer 出现、新用户目录下 host 与 coordinator 保持缺席；它不验证一轮对话是否走完）；真实任务验证（docker/container-gates.sh 的容器门禁与活体轮次）。package-fidelity-diagnostic.mjs 三方对照（官方参考 / 固定渲染包 / 重建包）且开局拒绝把诊断当交付；verify-publication-tree.mjs 用 git archive HEAD 树哈希证明导出无损。"这些检查通过"要按它实际断言的范围来读，README 的声明不算数。

scripts/verify.mjs · native-e2e-check.mjs · package-fidelity-diagnostic.mjs · verify-publication-tree.mjs · docker/container-gates.sh
C4

实证韧性细节：防的具体坑。错误进注册表不进字符串（SAND_ERROR_DEFINITIONS 带 retryable 标注，未注册错误在 emit 边界被重新分类，原始 code/payload 永不 ship）；host 锁带 PID 存活探测与升级接管（SIGTERM→SIGKILL，防锁残留卡死下次启动）；WriteEpoch 世代计数使过期写入失效（防乱序回写覆盖新值）；secret-store 全部 temp + rename 原子写。

shared/errors/registry.ts · host-lock.ts · write-epoch.ts · host-secret-store.ts
C5

实证隐私剥离：策略可判定，是否执行由开关决定。密钥模式正则剥除（sk- / ghp_ / xoxb / AIza / Bearer）；invariant 消息打包时剥离但保留调用链信息（防泄露 + 可定位）；PrivacyMode 五档。策略层是可测的纯函数：shouldRedact() 对 CREDENTIALS 与 UNSPECIFIED 一律判定需要脱敏，allowedPurpose() 按"模式 × 用途 × 分类"作答。但"有策略函数"不等于"默认已经脱敏"：是否真的代入策略由 resolveEnforceRedaction() 决定，其全局开关 isGlobalEnforcementEnabled() 默认 false，未启用时 getRedactionAwareDisplayValue() 原样返回未脱敏值——默认参数下（NO_STORAGE + CREDENTIALS）显示路径给出原值，只有显式 enforceRedaction: true 才得到脱敏标记。启用条件与调用路径需要单独核对；这是策略与开关的读码结论，不能当作生产环境凭据外泄的证明，反向也一样。

E

元认知：可迁移的判断系统

学了对我有什么用

这个仓库最值得学的是两套判断系统——原作者把安全承诺编译成结构，重建者把诚实编译成脚本。技术会过时，这两套系统可迁移到任何项目。

E1 · 四个可迁移范式

Pinned 身份思维

外部输入 = 不可变 + 校验身份。本项目对 DMG / app.asar 的每条获取路径都做 SHA-256，身份不符即删除重来。别处：供应链、可复现构建、"下载即校验"。

边界即约定

进程 / 协议边界按 API 设计并配验证。adapter 目录是"结构性约定"——新增不能静默替换、删除会报错。别处：微服务 / 插件系统先写边界约定再写实现。

保真度预算（混合架构分层）

先问"什么可重建且可验证、什么必须保留"。本项目：运行时可重建（有证据锚点），renderer 保留（无源码），分界处用"窄确定性 transform + 哈希记录"缝合。别处：任何 legacy 现代化 / 迁移，混合可以是正当的架构选择。

门禁即验收，按断言的实际范围读

把"成功"定义成可执行断言集，并拒绝为通过而削弱（clean-source 不得携带禁入证据）。每条断言证明什么要分清：产物组成可以证明（ASAR 清单、marker 数量、无 source map），启动可以证明（真实 spawn），而"一轮对话能跑完"要另找门禁（容器门禁与活体轮次）。别处：把验收标准写成脚本，测试失败 = 构建失败。
